  • The platform's QC measures the file the way the platform does, and it runs after you have sent it.
  • The specs are PDFs and partner portals that change without notice, and a number copied out of one carries no date.
  • A meter tells you a number. It does not know which rule applies to this file, for this destination.

What you do with it

Read the verdict, with the clause attached

Every rule gets PASS or FAIL, the measured value, the limit, the standard it comes from and the destination's own words. Under the findings it prints what would fix it, in decibels. Integrated and dialogue-gated loudness, true peak, loudness range, sample rate, bit depth, channel layout, packaging, padding, mono compatibility, the metadata's own loudness claim.

One HTML file with its type embedded. It opens offline, on a phone, and prints to A4; a PDF comes through the Chrome you already have.

Watch the bounce folder

Point cumple at the folder your DAW bounces into. Every file that lands gets a sheet next to it and a line in the folder's CSV log, once its size and modification time have held still. Sources are never touched or moved. The same watcher runs in the app's Watch tab, with a live table, or as cumple watch on a machine nobody looks at.

See where the loudness lives

The sheet shows the short-term loudness over time, the integrated value as a line, the destination's window as a band, and a dot on the loudest 3 seconds, so a failure points at a place in the programme.

Diff two versions, or stems against the printmaster

One sentence gives the gain change, the offset in samples and milliseconds, the polarity, the EQ as third-octave bars, and what is left once all of that is corrected. Stems summed against the printmaster are judged at level, so the residual is the real difference. The diff has its own sheet.

How we know the numbers are right

66 of 66 EBU Tech 3341 readings inside the published tolerance
29 of 29 cases of the official EBU Loudness Test Set v5.0
0.05 LU the largest gap to ffmpeg ebur128 and to pyloudnorm on integrated loudness
91x real time: 60 minutes of stereo measured in 39 s at 704 MB peak memory

Every measured number on this page comes from a report in the repository, and the disagreements are written down too. The dialogue gate is a labelled approximation of Dolby's algorithm: against two open films it read 1.6 LU low on Tears of Steel and 6.7 LU low on Sintel, whose dialogue sits under an orchestral score. docs/DIALOGUE.md has the method and the numbers. 0 tests with 91 % line coverage run on macOS, Windows and Linux.

39 destinations, every number with a source and a grade

A profile is one YAML file that quotes the document it comes from, names the grade of that access (READ, the primary document was read; SECONDARY, another standards body's table; COMMUNITY, the platform publishes nothing) and records the date it was read. Where a source is silent on a tolerance, the profile says the number is the tool's own default.

How it works

  1. Drop the bounce

    A file, a folder of bounces, or a delivery package of discrete mono files whose channel roles are read from the file names.

  2. Name the destination

    One of 39, grouped by family, with the grade of its source beside the name. Or add your own as one YAML file.

  3. Read the verdict

    PASS or FAIL per rule, the measured value, the limit, the standard, the source's words, and the fix in decibels.

  4. Send the sheet

    HTML or PDF next to the file, JSON beside it, and a CSV log for the folder. Nothing needs a terminal, a server or an account.

What it does that the meters do not

cumple measures with the same standards these meters implement, and adds the destination's rule, the source of that rule, and a sheet to send. Cells say "not checked" where the tool's own documentation was not read for this table.

Questions

Is cumple free?

Yes. MIT licence, no account, no server, no tier. The app and the command line are the same code, in one repository.

Does my audio leave the machine?

No. Nothing is uploaded. The only external program cumple runs is the Chrome, Chromium or Edge already on the machine, to print a PDF.

Which destinations does it know?

39, each with the grade of its source and the date the source was read. A destination you add is one YAML file in your config folder, and a pull request if you want everyone to have it.

How accurate is the meter?

All 29 cases of the official EBU Loudness Test Set pass, with 66 of 66 Tech 3341 readings inside the published tolerance, and integrated loudness lands within 0.05 LU of ffmpeg and pyloudnorm on the same files. The reports are in the repository and a script regenerates them.

Does it measure dialogue-gated loudness like the studios?

Approximately. Netflix, Amazon and Disney gate on dialogue with a Dolby algorithm nobody outside Dolby can run. cumple uses a heuristic speech detector, labelled as such on every sheet, that read 1.6 and 6.7 LU low on two open films; the full-programme value is always shown beside it, and Netflix's own fallback rule is applied before anything is flagged.

Which files does it read?

WAV, BWF, RF64, AIFF and FLAC, mono to 7.1 and packages of discrete mono files. Not AAC, AC-3, MP3 or MXF, and no Dolby Atmos or ADM checks yet. Check the master.

Which platforms?

macOS on Apple silicon and Intel, Windows 10 and 11 on x64, Linux on x86_64. The builds come from CI and are unsigned; the macOS build is the one exercised by hand so far. Any machine with Python 3.12 can install the command line with uv.

Honest limits

  • The dialogue gate is a heuristic and the weakest meter in the tool on film mixes; the numbers above say by how much.
  • No Dolby Atmos or ADM checks yet: cumple reads BWF metadata but does not validate beds, objects or track mappings.
  • It does not decode delivery codecs or MXF, does not find the 2-pop, and does not compare the audio to the picture.
  • Leq(m) for cinema rests on a stated convention, not a calibrated room; the stem null tolerance is the tool's default, since no studio publishes one.
  • The PDF needs a local Chrome, Chromium or Edge; the HTML sheet is written regardless and is the deliverable. The desktop builds are unsigned; Windows and Linux builds are self-tested in CI and not yet run by hand.

Free and MIT licensed.

The app and the command line are one MIT-licensed repository. There is no hosted version, no account and no tier.

If the destination you deliver to is not there, it is one YAML file with the clause quoted and the source graded, and a pull request. Every profile in the registry was built that way.

Download

One folder per platform, from the latest release. Unsigned, so the first launch takes one extra step.

  • macOS, Apple siliconcumple-macos-arm64.zip
  • macOS, Intelcumple-macos-x86_64.zip
  • Windows 10 and 11, x64cumple-windows-x86_64.zip
  • Linux, x86_64cumple-linux-x86_64.tar.gz
  1. macOS: unzip, move cumple.app to Applications, open it once and let macOS refuse, then System Settings, Privacy and Security, Open Anyway. The terminal route is xattr -dr com.apple.quarantine /Applications/cumple.app.
  2. Windows: unzip, run cumple-app.exe. SmartScreen shows "Windows protected your PC": More info, Run anyway. The app needs Microsoft's WebView2 runtime, which Windows 11 and most Windows 10 machines already have; when it is missing the app says so and opens the download page.
  3. Linux: untar, run cumple-app/cumple-app. The folder includes a .desktop file and an icon for the launcher.

Or install the command line with uv

uv tool install --python 3.12 git+https://github.com/victor10days/cumple
cumple check master.wav --spec netflix-2.0

Add "cumple[app] @ git+https://github.com/victor10days/cumple" for the window from Python (cumple[app-qt] on Linux), then cumple app. The README has every command with real output.
