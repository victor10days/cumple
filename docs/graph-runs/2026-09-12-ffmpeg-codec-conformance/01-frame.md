# 01 Frame: delivery codec and container conformance through an optional ffmpeg

Date: 2026-09-12. Run: `docs/graph-runs/2026-09-12-ffmpeg-codec-conformance/`. Branch: `loop/02-ffmpeg-codecs`. Roadmap item R2 in `docs/ROADMAP.md`, confirmed by Victor on 12 September together with R1; ranked second by the competitive landscape (3 of 9 QC platforms list codec and container conformance, 4 with Baton).

## Question

How does cumple measure a compressed or wrapped delivery (MP3, AAC, AC-3, E-AC-3, the audio in MXF, MOV and MP4) so that the destination's container clause fails on the file itself instead of the tool refusing to open it, without adding a runtime dependency and without letting a filename reach a shell?

## Capability contract (per ecc:product-capability)

- Who: a mix engineer or post supervisor running `cumple check`, `cumple info`, the watch folder or the desktop app on a delivered file.
- After this ships: a file libsndfile cannot open, whose suffix is one of `.mp3 .m4a .aac .mp4 .mov .ac3 .ec3 .eac3 .mxf`, is decoded by a local ffmpeg when one is on PATH (or named by `CUMPLE_FFMPEG`), measured exactly as a WAV is, and reported with the decoder named. The `format.container` finding fails a netflix-2.0 check on an MP3 with the quoted clause "Lossy or lossless audio compression is never allowed" and passes an acx check, whose profile lists mp3. `format.bit_depth` says the file is not PCM instead of printing "None-bit". Without ffmpeg the error names what to install.
- User-visible promise: nothing changes for WAV, BWF, RF64, AIFF and FLAC; the page's "Which files does it read?" answer and README's limit line say what is now read and that `diff` and `fix` still need PCM files.
- Fixed policy: no new Python dependency; ffmpeg is optional and never required by tests or CI outside the Linux job that installs it; every subprocess call is an argv list with `-nostdin`, an absolute regular file, a protocol whitelist, a timeout and a bounded stderr.
- Architecture preference: one new module `src/cumple/io/ffmpeg.py`; `reader.probe` and `reader.iter_blocks` gain the fallback; the engine's container mapping learns the new tokens; the watch folder keeps its suffix list (a growing MP3 is not a bounce this tool watches for).
- Open: whether the app's file dialog filter should list the new suffixes (left as is this iteration, the app calls the same reader).

## Constraints

- No new runtime dependency. Python 3.12, existing deps only.
- Security review (ecc:security-review) on the subprocess module before merge: argv list, no shell, path checks, `-nostdin`, `-protocol_whitelist file,pipe`, timeouts, stderr capped, no user-controlled options.
- Tests skip cleanly when ffmpeg is absent; the CI Linux job installs ffmpeg with apt so the decode tests run there; macOS and Windows jobs skip them.
- Every doc that names the readable formats changes in the same PR (README limit line, the page FAQ and its JSON-LD twin, which a test holds equal).
- The benchmark re-pin rides in this PR (Victor, 12 September: accept the machine's ffmpeg 9.0.1 and re-pin through the report script). `docs/BENCHMARK.md` is regenerated by `scripts/benchmark_meters.py`; RELATED.md's ffmpeg and loudcheck sections say which ffmpeg produced the run and when; any page figure the run changes is re-derived by the existing tests.
- Prose without dashes; no claim without a run; counts re-pinned from pytest's own line.
