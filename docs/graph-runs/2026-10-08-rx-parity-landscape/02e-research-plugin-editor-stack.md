Can a plugin run Python? No, not inside the plugin process. GitHub searches ("python vst", "python audio plugin", "numpy audio plugin", "pyo vst", "juce python", "python clap plugin") found only PyoVST (no licence, 0 stars, 2020) and juce-python (MIT, 1 star, 2021). pedalboard and DawDreamer (both GPL-3.0) work the other way round. Reported blockers: GIL contention between plugin instances, unbounded allocation and garbage collection, numpy per-call overhead at block sizes around 256 (JUCE forum thread 7284; LAD June 2009). Running Python in a separate process is realistic: the RX Connect pattern.

Architecture options. (a) C++ core with nanobind bindings: nanobind BSD-3, 3740 stars; pybind11 BSD-3 by file; build with scikit-build-core (Apache) and cibuildwheel (BSD-2). One DSP implementation; VST3, CLAP, ARA and AU SDKs are all C or C++, so the plugin needs no foreign-function layer. Cost: cumple becomes a compiled package; the release matrix already builds macOS arm64 and x86_64 (`release.yml`), PyInstaller will bundle the extension. (b) Rust core with PyO3 (MIT/Apache, 16211 stars), maturin, rust-numpy (BSD-2): good core; plugin side weak: nih-plug in maintenance mode, VST3 export GPLv3, nice-plug experimental, clack (Apache, 241 stars) low-level; AU only through clap-wrapper; no Rust ARA binding found. (c) Python offline engine plus a separate plugin: two implementations drift, every test doubled; only worth it if the plugin is a thin viewer. (d) Python inside the plugin: rejected.

Recommendation: (a), in three stages. 1. Build the editor as HTML, JS and WebGL inside cumple's existing pywebview app, on top of the numpy STFT engine; serves Victor's own use first, DAWs call it as an external editor the way Noise Canvas works. 2. Port the STFT core to C++: pocketfft C++ so numerics match numpy, Signalsmith for the rest; expose through nanobind; keep the numpy version as the test oracle. 3. Wrap as a plugin with a CLAP core, clap-helpers, clap-wrapper for VST3 and AU; reuse the same web UI through choc's WebView; add ARA from the ARA SDK. Everything MIT, ISC or Apache. Fall back to JUCE (ARA built in) only if ARA through clap-wrapper stalls; the plugin binary would then be AGPL while cumple's core stays MIT.

What the plugin must do. ARA versus a plain insert: with ARA the plugin can "read audio samples from the DAW host at will" (ARA README); a plain insert sees only live buffers; editing a past region would need capture into plugin state plus host transport position (inference). SpectraLayers ships only as "VST3 ARA and AAX ARA"; "The DAW will automatically save SpectraLayers Pro modifications within its project"; its File menu is unavailable in ARA mode (SL11 help). RX 8's RX Connect "sends a clip, or multiple clips, to the RX 8 standalone application" with a Send For Repair and send-back round trip (local manual). RX Spectral Editor has run as ARA since RX 9; RX 11.1 added Pro Tools and Studio One; Logic runs only under Rosetta (secondary sources: Creative Cow, Celemony). Acoustica 7.4's ARA2 plugin offers "the complete functionality of Acoustica's clip editor", Premium only (press release). Latency: CLAP `latency.h` and the VST3 and AU equivalents (not read); a real-time STFT path reports its window latency; an ARA renderer can read ahead (inference). Offline render: CLAP `render.h`, `CLAP_RENDER_OFFLINE` means the plugin "may use more expensive algorithms". Undo: CLAP draft `undo.h` lets the plugin "merge its undo history with the host"; ARA does not sync history (Steinberg forum 135861); so keep a non-destructive edit list (region, operation, parameters) rendered from the source audio; the same list gives A/B. Signing: `release.yml` has no codesign or notarise step; Pamplejuce (MIT, 770 stars) shows notarisation in CI; forums disagree on whether plugin bundles strictly need notarising.

Unknowns: no FFT benchmarks run; whether clap-wrapper passes ARA through for AU (only the VST3 file found); whether nice-plug dropped the GPLv3 vst3-sys bindings; WKWebView stability inside Logic and Pro Tools; which SDK version brought the VST3 MIT change; exact text of JUCE EULA clause 2.3; Apple Developer Program cost and whether plugins must be notarised; RX 9 to 11 ARA details come from news; Acoustica 8's ARA tools; Codeberg and GitLab not searched.

SUMMARY: the plugin cannot run numpy in-process, so: a C++ core with nanobind, a shared WebGL UI, and a CLAP, clap-wrapper and ARA SDK shell (all MIT, ISC or Apache), JUCE as the AGPL fallback; no permissively licensed brush or lasso spectral editor plugin found. CONCERNS: ARA through clap-wrapper verified for VST3 only; webview stability in hosts and FFT speeds unmeasured; RX ARA facts from secondary sources.
