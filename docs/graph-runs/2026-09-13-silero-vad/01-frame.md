# 01 Frame: Silero VAD as an optional dialogue-gate backend

Date: 2026-09-13. Run: `docs/graph-runs/2026-09-13-silero-vad/`. Branch: `loop/03-silero-vad`. Roadmap item R1 in `docs/ROADMAP.md`, ranked first by the competitive landscape (3 of 21 comparables list a dialogue gate of the Dolby Dialogue Intelligence class; 6 profiles name the algorithm) and confirmed by Victor on 12 September as the loop's item alongside R2.

## Question

How does cumple offer a second, neural speech detector for dialogue-gated loudness (Silero VAD, MIT) behind an optional extra, measured on the same two open films as the heuristic, without changing the default, the report's honesty about what the gate is, or the install time of the base package?

## Capability contract (per ecc:product-capability)

- Who: a mix engineer checking a film or series mix against a destination whose loudness clause is dialogue-gated (Netflix, Amazon, Disney, Apple TV, ATSC A/85 long-form).
- After this ships: `cumple check --vad silero` (or `CUMPLE_VAD=silero`) runs Silero VAD v6.2 through onnxruntime instead of the heuristic for the speech mask; the speech share, the dialogue-gated value, the finding notes, the JSON (`speech.backend`) and the sheet footer name which backend produced the mask; the heuristic stays the default and `--vad heuristic` is explicit. Without onnxruntime, `--vad silero` fails with a message naming `pip install "cumple[vad]"`. `docs/DIALOGUE.md` reports both backends on the same films, and README's limits bullet carries Silero's measured numbers beside the heuristic's.
- User-visible promise: nothing changes for anyone who does not pass `--vad`; the base install gains one 2.3 MB model file and no dependency; the report never calls either backend Dolby's algorithm.
- Fixed policy: the model is bundled (Silero VAD, MIT, `src/cumple/models/silero_vad.onnx`, licence file beside it), never downloaded at run time; inference is offline; onnxruntime is the only new dependency and only in the `vad` extra (and the dev group, so CI runs the tests); the false-pass WARN on a dialogue-gated pass keeps firing for both backends and names the backend.
- Architecture preference: one new module `src/cumple/meters/vad.py` with a `SileroDetector` that has the same `feed` and `result` interface as `SpeechDetector` and composes one for levels and frames; the mask dilation rule moves to a shared function in `dialogue.py`; `scripts/dialogue_benchmark.py` uses the detector instead of its own inference so there is one implementation.
- Open: whether the desktop app exposes the choice (left as is; it calls `measure` with the default), and whether the frozen apps bundle onnxruntime (they do not this iteration; the model rides along as package data).

## Constraints

- No new dependency in the base install. `[project.optional-dependencies] vad = ["onnxruntime>=1.17"]`; the `dev` group gains `onnxruntime>=1.17` so the tests run in CI on all three runners.
- Streaming: the detector must not hold the whole programme in memory; the picked channel is resampled to 16 kHz in chunks and fed to the model in 512-sample windows with carried state.
- Every report surface that says "heuristic" today says the backend's name instead, derived from one field; no string is duplicated.
- Test fixtures: a 3 s public-domain LibriVox excerpt at 16 kHz mono (96 KB) committed under `tests/fixtures/` with its provenance; no other audio in the repo.
- `docs/DIALOGUE.md` is regenerated by `scripts/dialogue_benchmark.py` only; README's dialogue numbers and the page's are derived from it by tests (`tests/test_site_numbers.py`), so whatever the run says, the page says.
- Prose without dashes; no claim without a run; counts re-pinned from pytest's own line; no push to main; the implementing context never grades.
