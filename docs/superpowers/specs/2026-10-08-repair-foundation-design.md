## Goal

`cumple repair <file> --chain "declick(),declip()" --out <copy>` writes a repaired copy of a PCM file through a compiled DSP core, leaves a sidecar receipt that says exactly what ran, and `docs/REPAIR.md` scores the two modules against ffmpeg and cathar on synthetic damage with a held clean reference, with RX 8 columns ready for Victor's Batch Processing outputs. The core is the one implementation that the desktop app and, later, the plugin will share.

## Non-goals for build 1

- No module beyond De-click (with Interpolate as its gap filler) and De-clip. cathar's `declip.rs` carries six methods; build 1 ports A-SPADE (the default, and the survey's preferred family) and the cubic fill (the cheap fallback cathar itself uses at file edges). Social sparsity, constrained OMP, NMF and the unfolded-ISTA method stay in cathar until the harness has RX scores to rank them against; each would need its own fidelity test, and the plan does not pay for four of them before one is scored.
- No change to the click detector's method. cathar's detector compares each sample with the RMS of a window that contains the sample itself, so the ratio can never exceed sqrt(window) (8 at window 64; both skeptics proved and measured it). Build 1 ports it as it is, with defaults inside that bound, and names the bound in the parameter help and the report. The AR-residual detector that replaces it is build 2 (R11).
- No change to any meter, check, profile, report or to `fix`. `measure()` is called by the repair runner, never modified.
- No editor, no plugin, no C ABI. The crate layout leaves room for both (see Architecture) and nothing more.
- No Interpolate beyond cathar's 2,048-sample solve: build 2 (R11).
- No model weights, no network at run time.
- The frozen desktop apps do not carry the extension until build 5; `release.yml` is untouched (it still runs on the pull request because its paths include `pyproject.toml` and `uv.lock`; it syncs `--extra app` only and never sees the extension).
- PySide6 replaces PyQt6 in a separate one-PR fix (R15), a precondition of the next release, not part of this build.

## Architecture

Three layers, one direction of dependency: the Rust core knows nothing about Python; the Python package imports the core only inside `cumple.repair`; the CLI and app call `cumple.repair`.

### 1. The core: `crates/cumple-dsp`

A pure Rust library crate, `MIT`, no C dependencies, in a Cargo workspace rooted at the repository (`Cargo.toml` at the root lists `crates/cumple-dsp` and `crates/cumple-dsp-py`; the plugin shell later adds a `capi` crate beside them). Edition 2024, `rust-version` 1.87, matching cathar so the port compiles unchanged where it is unchanged.

Contents:

- `stft.rs`: a streaming STFT and inverse STFT on `realfft` (3.x) and `rustfft` (6.x), f64 throughout. `Stft::new(n_fft, hop, Window::HannPeriodic)` (a `Window::HannSymmetric` exists for the A-SPADE port's tests, dividing by `n_fft - 1` as cathar's `util.rs` does), one-sided spectra, overlap-add synthesis with the window-squared overlap sum divided out; `analyze` and `synthesize` take slices and write into caller-owned buffers. It is checked against scipy's `ShortTimeFFT` (which runs on ducc0, BSD-3, in scipy 1.18.1) within 1e-9 absolute on unit-scale signals, constructed with `phase_shift=None` (scipy's default references each slice's phase to its centre, which flips odd bins against a plain windowed FFT) and with the column offset computed from `sft.p_min` rather than assumed; and for perfect reconstruction (analysis then synthesis) within 1e-10 for the periodic Hann at hop n_fft / 4 away from the edges. In build 1 the shared `Stft` serves the oracle test and the tiles the editor will need; neither ported module runs through it (see `declip.rs`).
- `module.rs`: the module contract, a trait:
  - `fn id(&self) -> &'static str` and `fn version(&self) -> &'static str`;
  - `fn context_frames(&self) -> usize`: how many samples of neighbouring audio the module needs on each side of a block to process it as if it had the whole file;
  - `fn latency_frames(&self) -> usize`: 0 for every build-1 module; reported so the runner and later the plugin can compensate;
  - `fn process(&mut self, input: &[f64], output: &mut [f64], edge: Edge)`: input is one channel of one block plus its context on both sides; output is the same length; the runner keeps the centre; `Edge` says whether the left or right context is the true start or end of the file (so the port can take cathar's end-of-file branches) and how many trailing samples are padding;
  - `fn flush(&mut self, output: &mut [f64]) -> usize`: anything a latency-carrying module still holds; 0 in build 1;
  - `fn report(&self) -> Report`: what happened, as counts and positions (clicks repaired and where; gaps that hit the solve cap or the context cap; clipped runs rebuilt, the longest run, the peak restored, iterations), serialised to JSON by the Python side and copied into the receipt.
  - Buffers are allocated once per module from `context_frames` and the block size; `process` allocates nothing per sample. "Allocation-free" means that, not that the Rust side never calls the allocator during setup.
- `declick.rs`: the port of `declick_with_method`, `local_rms` and `cubic_interpolate` from cathar `restore.rs` (lines 116 to 213 at commit f2c2842), and `inpaint.rs` from cathar's `inpaint.rs` (286 lines; its AR estimate, Levinson recursion and banded solve already run in f64 upstream). Parameters: `threshold` in local-RMS multiples, default 5.0 (cathar's own unit tests use 5; its CLI default of 10 at window 64 is above the bound and never fires), `window` in samples, default 64 (cathar's CLI fixes 64), `method` `ar` or `cubic`, `iterations` (cathar passes 3). The parameter model rejects `threshold >= sqrt(window)` with the reason. cathar's `local_rms` window for sample `i` covers samples `i - 31` to `i + 32` (restore.rs 171 to 194). A lone non-zero sample in digital silence therefore has a ratio of exactly sqrt(window), so any threshold below that fires on it. The skeptic found 11 such one-LSB detections in 5 of the 10 clean SQAM tracks at threshold 5. The parameter help and README say so, and the harness counts these detections as false ones.

cathar's `MAX_SOLVE = 2048` linear-fill fallback is kept and named in the report when it fires. Context: `inpaint_gap` reads `max(4 * gap, 8 * p, 1024)` samples on each side of a gap for its AR estimate (`inpaint.rs` lines 37 to 42), 8,192 for the longest gap it solves. So `context_frames` is 16,384 (8,192 of reach, 2,048 of gap, 8 of shoulder, rounded up).

At the file's own ends, the port does what upstream does: it clips the AR context at the end of the audio and still solves AR (inpaint.rs 41 to 42). Only a gap whose context would reach past a chunk edge that is not a file edge is filled linearly and counted as a context fallback. `inpaint_gap` is told which ends of its slice are the file's.
- `declip.rs`: the port of `declip_spade`, `frame_starts`, `hard_threshold_k`, `project_gamma` and the cubic fill from cathar `declip.rs` (712 lines). The port keeps cathar's algorithm exactly: a symmetric Hann frame of 1,024 at hop 256 with a flush frame when the length is off the hop grid, a full complex 1,024-point FFT with `1/sqrt(L)` scaling, the hard threshold ranking all 1,024 complex bins with ties kept at the cutoff, `k` growing by `RELAX_BY = 2` on every iteration, at most `MAX_ITER = 100`, the residual summed over all bins and compared with cathar's `eps`, and the projection that returns every unclipped sample unchanged. It uses the same `rustfft` planner the shared `Stft` uses but not the shared one-sided frame, because the one-sided periodic variant moves rebuilt samples by 0.11 and ΔSDR by up to 1.3 dB on the fixture (03b and 03c measured it). Parameters: `threshold` as a linear sample value in `[1e-4, 1.0]`, default 0.95 for a user's CLI call (a file clipped at full scale), always the manifest's clip level in the harness; `method` `spade` or `cubic`. Context 4,096 (four frames).
- Two precisions (Victor's decision, 2026-10-08, after two tolerance designs for comparing an f32 upstream with an f64 port had failed):
  - **Generic code.** `declick.rs`, `inpaint.rs`'s callers and `declip.rs` are generic over the sample type `F: num_traits::Float`, with two instantiations, `f32` and `f64`. `inpaint_gap` solves in f64 in both, as upstream does (inpaint.rs copies the segment to f64).
  - **The f32 instantiation is the fidelity build.** It does cathar's arithmetic in cathar's order: the f32 running sum in `local_rms`, `FftPlanner::<f32>` in `declip_spade`, and f32 sample storage. It runs on the same `rustfft` and `realfft` versions cathar's `Cargo.lock` pins at f2c2842 (6.4.1 and 3.5.0, pinned with `=` in the workspace).
  - **The f64 instantiation is what ships.**
  - **What is compared.** The f32 build is compared with cathar; the f64 build is compared with the f32 build, and that difference is the precision effect, reported but never a gate.
  - **Architecture.** rustfft picks its SIMD path at run time (NEON on aarch64, AVX or SSE on x86_64), so cathar and the port are always compared on the same machine.
- `lib.rs`: re-exports; `THIRD_PARTY.md` beside `Cargo.toml` carries cathar's MIT text with "Copyright (c) The cathar Authors", the commit the port was taken from, and the list of ported functions, plus the rust-numpy notice (BSD-2-Clause, Toshiki Teramura), which a wheel that links it must carry. Every ported file starts with a comment naming its source file and commit.

Why chunked with context rather than whole-file: cumple's reader streams 262,144-frame blocks (`io/reader.py`, `DEFAULT_BLOCK_FRAMES`) in constant memory, and the plugin will stream too. A click or a clipped run is local; A-SPADE's hard threshold is sensitive to tiny magnitude changes (a different bin survives a tie and every rebuilt sample moves), so a chunked run differs from a whole-file run by amounts the skeptics measured: 0.25 in sample value and 0.29 dB ΔSDR at 8,192-sample blocks. At 262,144 nothing is measured yet beyond 03b's emulation, which found 0.00 dB on a 30 s LibriVox excerpt. Task 6 measures it. The scoring rule therefore measures port fidelity whole-file and the chunking cost separately.

### 2. The bindings: `crates/cumple-dsp-py`

A PyO3 `cdylib` built by maturin into the Python distribution `cumple-dsp`, import name `cumple_dsp`, abi3 for CPython 3.12 and later. Its `[project]` has a static `version = "0.1.0"`, because a dynamic version makes `uv lock` run maturin and bootstrap a toolchain. It depends on the core under another name, `dsp = { package = "cumple-dsp", path = "../cumple-dsp" }`. The `#[pymodule] fn cumple_dsp` macro emits a module named after the function, which shadows a dependency also called `cumple_dsp`: the re-check's scratch build failed with E0659.

It exposes:

- `cumple_dsp.__version__` and `cumple_dsp.core_version()` (the crate versions, which go into receipts);
- `cumple_dsp.Stft(n_fft, hop, window="hann")` with `analyze(x) -> complex128 (frames, bins)` and `synthesize(spec, length) -> float64`, for the tests and later the editor's tiles;
- `cumple_dsp.Declick(samplerate, threshold=5.0, window=64, method="ar", iterations=3, precision="f64")` and `cumple_dsp.Declip(samplerate, threshold=0.95, method="spade", precision="f64")`. `precision="f32"` selects the fidelity build: numpy's float64 input is cast to f32 inside, which is exact for the float32 files the harness writes, and the output is cast back. Each has `context_frames`, `latency_frames`, `process(block: ndarray[float64, (frames, channels)], edge=...) -> ndarray` that runs each channel through its own module instance, `flush() -> ndarray`, and `report() -> dict`; and `process_whole(x) -> ndarray`, one call over an entire signal, which the fidelity tests use.

Numpy arrays cross through the `numpy` crate as read-only views in and freshly allocated arrays out, one allocation per block. The GIL is released during `process` with `py.detach` (PyO3 0.26 renamed `allow_threads`; the plan pins the current release). The crate does not enable pyo3's deprecated `extension-module` feature; maturin 1.9.4 or newer handles the linking, and `cargo test` runs on the core crate only.

`pyproject.toml` at the root gains `[tool.uv.workspace] members = ["crates/cumple-dsp-py"]`, `[tool.uv.sources] cumple-dsp = { workspace = true }` and the extra `repair = ["cumple-dsp"]`. The dev group does not carry it, so `uv sync` still works on a machine without a Rust toolchain; CI runs `uv sync --group dev --extra repair` after installing stable Rust, and the tests that need the core skip when `cumple_dsp` is not importable, the way the Silero tests skip without onnxruntime. uv rebuilds a workspace member only when its `pyproject.toml` changes. So the member declares `tool.uv.cache-keys` over both crates' `Cargo.toml` and `src/**/*.rs` and the lockfile, and every Rust edit is still followed by an explicit `uv sync --extra repair --reinstall-package cumple-dsp`, with no exception. The re-check found that the cache keys make `uv sync --extra repair` rebuild, but a bare `uv run`, which every "run everything" step uses, kept the old build (03d Concern 7), and 03b and 03c both saw a mutated extension test against the stale build. `cumple[repair]` installed from git compiles Rust on the user's machine; the install hint and README say so. The name `cumple-dsp` is not registered on PyPI; reserving it is Victor's, and until then the extra resolves only through the workspace or the git route. hatchling stays the build backend of `cumple` itself.

### 3. The Python side: `src/cumple/repair/`

- `params.py`: one pydantic model per module with `extra="forbid"`, ranges (`threshold` for De-click in `[1, 8)` at the default window with the sqrt(window) bound checked in a validator, `window` in `[8, 1024]`; `threshold` for De-clip in `[1e-4, 1.0]`), units and help text; `ChainStep(module, params)` and `Chain(steps, id, summary)`. The JSON schema of these models is what the app's forms will read later. The models carry no `module_id` or `module_version` (this draft first read them from the core at import): `params` must import without the core, for `--list-presets` and the path that reports a missing core, and the receipt records the core's versions (`cumple_dsp_version`, `core_version`) instead.
- `chain.py`: parse the one-line form `declick(threshold=5),declip(threshold=0.95)` and the YAML form (the strict style of the specs profiles: unknown keys fail), round-trip between them, load built-in presets from `src/cumple/repair/presets/*.yaml` and user presets from `$XDG_CONFIG_HOME/cumple/repair/*.yaml` (default `~/.config/cumple/repair/`). A user preset overrides a built-in with the same id. `chain.user_repair_dir()` applies the same `XDG_CONFIG_HOME` rule as `specs/registry.py`'s `user_dir()` (lines 28 to 30). It does not call `user_dir()`, which returns the profiles folder.
- `runner.py`: `repair_file(src, chain, dst, residual=None) -> RepairResult`. Reads with `iter_blocks` (float64, `DEFAULT_BLOCK_FRAMES`), keeps a context tail per module of `context_frames` on each side, feeds each block plus context to each module in chain order, writes the centre of each output block, and at the end drains `flush`. Context semantics, stated so the tests can measure them: the left context is the module's own previous output (a chained module sees repaired audio behind it, as upstream would after a whole-file first pass); the right context is the raw lookahead block for every module in the chain (the first module has not processed it yet); the file's first block has no left context and its last block carries its true length, both passed through `Edge`, so the port can take cathar's edge branches instead of seeing zeros. The chain cost of raw right context is measured by a two-module test against the whole-file reference and reported. Writes as `fix.apply` does: same sample rate, channels, subtype and format; a temporary name beside the destination; `os.replace` once the copy is complete; refuses a destination that resolves to the source, a directory, or a file ffmpeg decoded (PCM only, as `fix`). Does not copy bext or iXML metadata (as `fix`; the CLI says so). `--residual` writes input minus output through the same path, which is the "output clicks only" view RX offers.
- `receipt.py`: the sidecar `<dst>.cumple-repair.json`: cumple version, `cumple_dsp` versions, the chain in YAML form and as parsed parameters, the input path and SHA-256, the output SHA-256, `measure()` summaries before and after (integrated loudness, true peak, sample peak, the clipping count cumple already reports), each module's `report()`, and wall time. The receipt is written after the copy is in place; a failure before that leaves no receipt and no copy.
- `metrics.py`: pure numpy, no extension needed: `sdr_db(reference, estimate)`, `delta_sdr(reference, damaged, estimate, mask=None)`, `residual_clicks(reference, estimate, positions, widths, threshold)`, `peak_error_db(reference, estimate, mask)`. Used by the harness and by the tests.
- `__init__.py`: `available() -> bool` and `require()` that raises `RepairUnavailable` with the install route (`uv tool install "cumple[repair]"` from git, which compiles the Rust core and needs cargo; never `pip install`, since cumple is not on PyPI).

### 4. The CLI

`cumple repair PATH --chain TEXT | --preset ID --out PATH [--residual PATH] [--receipt PATH]` in `cli.py`. Exit codes: 0 wrote the copy; 1 nothing to change (every module reports zero events; no copy is written); 2 an error (unreadable file, bad chain, missing extension, destination equals source). This differs from `fix` in one place: `fix` exits 0 on "already complies; nothing to change" (`cli.py` lines 452 to 454) because a passing file is its goal, while a repair that found nothing is worth a distinct code to a batch script. Every print that interpolates an exception or a path goes through rich's `escape()`. Output names the copy, the receipt, and a one-line summary per module from its report. `cumple repair --list-presets` prints the built-ins.

### 5. The harness

`scripts/make_repair_set.py`: builds `~/.cache/cumple/repair/` from the references `scripts/fetch_real_dialogue.sh` already fetches under `~/.cache/cumple/real-dialogue/` (the SQAM set, under the EBU terms the script records at its line 12, research use only, never committed; and the LibriVox chapter), decoded through `cumple.io.reader.read`. It uses the ten SQAM tracks the declipping survey's `Sounds` folder names (a08 violin, a16 clarinet, a18 bassoon, a25 harp, a35 glockenspiel, a41 celesta, a42 accordion, a58 guitar, a60 piano, a66 wind ensemble) when present, and says which were present. It also uses three 30-second excerpts of the LibriVox chapter at offsets 60 s, 600 s and 1,200 s. The whole 25.9-minute chapter is 133,603 A-SPADE frames, about 2.04 GiB per complex128 frame array, per level and tool. The fixture itself is a reference too, so its pinned rows exist. Damage, with fixed seeds recorded in a manifest JSON: hard clipping to the survey's seven input-SDR levels (1, 3, 5, 7, 10, 15 and 20 dB, from the survey paper and its companion page, not its README, which names no values), and clicks in two sets, both at threshold 5:
- **Impulse**: widths 1 to 3 at 32 times the local RMS. The re-check measured these 100 % visible to the detector of record on the fixture and on a tone. A click's `position` is its peak sample.
- **Burst**: widths 4 to 64 at 8 and 16 times the local RMS, in a separate table. Most of these are invisible to the detector of record by its arithmetic bound: a click of width w that dominates its window reaches only about sqrt(128 / w) of its local RMS. The table reports the miss rate per width as that detector's real weakness, and build 2's detector is scored on it.

The first amendment's impulse set (widths 1 to 8 at gains 8 and 16) had been calibrated at threshold 4. At the shipped threshold of 5, only 30 to 38 % of it was visible (03d Concern 2).

Every damaged file is written as 32-bit float. At gain 32 about 40 % of the fixture's clicks peak above full scale (03e measured 801 of 2,000, median peak 0.77, max 4.34), and a PCM file would clip them, changing the damage the harness scores.

The manifest holds every reference SHA-256, every damaged file's SHA-256, the clipping threshold per file as the float32 repr of the stored value, the click positions and widths, and for the RX folder the scale applied (below).

`scripts/benchmark_repair.py > docs/REPAIR.md`: runs cumple (`cumple repair` with the `declick` preset at threshold 5, and `declip(threshold=<manifest value>)` per file), ffmpeg `adeclick` and `adeclip` at their defaults (the ffmpeg on the machine, version printed; `adeclip` detects relative to the window maximum, so it needs no threshold), cathar `declick --threshold 5` and `declip --threshold <manifest value>` from a binary built at the pinned commit (`cargo install --git https://github.com/vbasky/cathar --rev f2c2842f89084589d069e5a8a0b61311aa70d928 cathar-cli --locked`; it writes 32-bit float WAV), and reads RX 8 outputs from `~/.cache/cumple/repair/rx8/` when they exist. RX 8's De-clip has an absolute threshold too, so the recipe's input folder holds each clipped file scaled so its clip level sits at 0.95 of full scale, the scale recorded in the manifest, and the harness divides RX's output by the same scale before scoring. Metrics per file and level: ΔSDR on all samples and on damaged samples only, residual click count and false detections (De-click), restored-peak error in dB (De-clip), wall time; and for cumple the chunking cost (next section). The RX columns print "not run" when the folder is absent. cumple appears three times:
- the shipped f64 build, which is the column scored against the others;
- the f32 build's fidelity to cathar (rule 1);
- the precision effect between the two (rule 1b).

Each tool also gets a line counting the damaged files it left unchanged. A baseline that changes nothing makes its comparison vacuous, so a non-zero count is flagged in the header. The script refuses to write if ffmpeg or the cathar binary is missing, as `benchmark_meters.py` refuses without the EBU set, and prints what to install.

`tests/test_repair_numbers.py`: the tables in `docs/REPAIR.md` are parsed as `test_site_numbers.py` parses `BENCHMARK.md`; the summary lines must equal the table means; one short fixture (`tests/fixtures/speech-librivox-3s.wav`, damaged in the test with the harness's own functions and seed) is re-run through the core and its ΔSDR must match the pinned figure within 0.05 dB. This test skips without the extension.

`docs/repair/rx8-recipe.md` is for Victor. It gives:
- which RX 8 modules to use, with every parameter value spelled out rather than a preset name. `Presets/De-click` and `Presets/De-clip` on Victor's machine hold no "Default" file, and the factory De-clip thresholds run from -0.25 dB ("Subtle Digital Clipping", which would see nothing on the scaled input) to -6.6 dB. De-clip's threshold is set to -0.5 dBFS, just under the scaled plateau at 0.95 (-0.45 dBFS); RX's Suggest button is not used, and the value is recorded in the manifest. De-click runs at the values the module shows when it opens, read off and recorded;
- the scaled input folder and why it is scaled;
- the output folder and the file naming RX Batch Processing uses;
- the SHA-256 manifest to fill in, so the harness can refuse a mismatched set.

## Scoring rule for build 1

Build 1 is done when, on the harness set:

0. Every module and every baseline does something. On every damaged file the module's damage can be seen in, cumple's and cathar's outputs both differ from the input. A no-op passes nothing: the first draft of this spec would have passed two of them (03b, 03c).
1. Port fidelity, measured whole-file with the f32 build (section 1, "Two precisions"). Each damaged file goes through `process_whole` at `precision="f32"` (one call over the entire signal) and through the cathar CLI at the pinned commit, at the same threshold, on the same machine. The two do the same arithmetic in the same order on the same FFT library, so they are expected to agree to the last few float32 units.
   - **De-click:** the same gap list (every start and width equal), every sample within 1e-6, and ΔSDR(all) within 0.01 dB.
   - **De-clip:** every sample within 1e-6, unclipped samples exactly equal, and ΔSDR(all) within 0.01 dB. ΔSDR(clipped) is not a second check: with unclipped samples exactly equal, it is the same ratio.
   - **These bounds are not tolerances to tune.** A failure means the port's arithmetic differs from cathar's somewhere: an order of operations, a cast, a window, a tie. The build stops and the difference is found, never widened.
   - **Why it changed.** Both earlier designs compared an f64 port with an f32 upstream, and both failed. A flat 0.1 dB failed a correct port on short files (03d). A per-file spread measured nothing, and a drift exclusion failed a correct port about once in seven click layouts (03e).
1b. Precision effect, measured and reported, not gated. The shipped f64 build is compared with the f32 build on every file: ΔSDR difference, largest sample difference, and for De-click the gaps on which the two builds' detections differ, which sit where cathar's f32 running sum drifts. All are printed in `docs/REPAIR.md`. This is what moving to f64 changes, and it is the f64 build that is scored against ffmpeg, cathar and RX.
2. Chunking cost, measured and reported, not gated. The chunked run at `DEFAULT_BLOCK_FRAMES`, with the stated contexts, is compared with the whole-file run of the same f64 build: ΔSDR difference and largest sample difference per file, printed in `docs/REPAIR.md` and pinned by the test within a tolerance so it cannot drift silently. Only references longer than one block are chunked; shorter rows, the fixture among them, read "not run (shorter than one block)". De-click is expected to match whole-file within 1e-9, because its context covers the AR reach. For De-clip, no figure is expected in advance.
3. Nothing outside the module's own work changes.
   - **De-click:** the output equals the input within 1e-9 outside the gaps the module reports, dilated by the shoulder pad (8 samples). Detections that are not injected clicks, such as the one-LSB samples in digital silence, are counted as false detections in `docs/REPAIR.md`, not hidden by a mask.
   - **De-clip:** every unclipped sample equals the input exactly, with no dilation, because the projection returns them unchanged.
4. Every column of every table is a number or "not run"; no "not checked".
5. `uv run pytest` is green on all three runners with the extension built. ## Risks carried into the plan

- The De-click detector of record cannot see wide or weak clicks (the sqrt(window) bound), and it fires on lone LSBs in digital silence. The harness reports its miss rate on the burst table and its false detections as the baseline's real weaknesses, and build 2 replaces it.
- The f32 build may not match cathar to 1e-6 on the first try: a missed cast or a reordered sum is enough. That is the point of the rule. Finding the difference is part of Tasks 3 and 4, and `06-build-1-notes.md` records each one. If a difference cannot be found within the task, the build stops and Victor sees the figures; the bound does not move.
- Pinning `rustfft` and `realfft` to cathar's versions holds the workspace back from their updates until build 2 decides whether fidelity to cathar still matters.
- Rust on three CI runners adds a toolchain install and a cache to `tests.yml`. The Linux runner builds cathar; how long that takes uncached is measured on the first CI run and recorded, not assumed. `release.yml` is untouched; the re-check confirmed that its `--extra app` sync does not build the Rust member.
- The SQAM set is fetched by an existing script under research-only terms; the tables say which references were present, and LibriVox alone is enough for the pinned numbers.
